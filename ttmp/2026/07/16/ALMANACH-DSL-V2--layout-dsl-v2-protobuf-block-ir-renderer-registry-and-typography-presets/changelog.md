## 2026-07-16

Step 1: Created ticket + self-contained handoff (protobuf block IR, renderer registry from rag-evaluation-system, typography presets+defaults, data-driven themes, per-block render options). Researched org IR-renderer and protobuf Go/TS patterns. 6 phase tasks.

Step 2 (Phase 1 complete): Added Buf v2 setup (`buf.yaml` scoped to `proto/`, `buf.gen.yaml` with local plugins), authored `proto/almanach/layout/v1/layout.proto` (Layout, Block, TextStyle, Typography, Theme, ThemeColors, RenderOptions + TextCase/RasterMode enums, `schema_version`, Struct block content). Generated Go (`gen/`) + TS (`web/src/pb/`). Added Go codec `internal/layoutpb` and a shared golden fixture with round-trip decode tests on both sides (Go `go test`, TS `node`). Wired `make proto` / `make test-proto` and `pnpm test:proto`. No behavior change — types only.

Step 3 (Phase 2 complete): React renderer registry. Added `web/src/blocks/registry.js` (defineBlock, createBlockRegistry with dup guard, mergeBlockRegistries, resolveBlockAdapter) + node unit test. Refactored `almanach-studio.jsx` from the `RENDERERS` object map to `BLOCK_ADAPTERS`/`BLOCK_REGISTRY` with an `UnknownBlock` placeholder and a `renderBlock(block, ctx)` dispatch; `parseLayoutJson` keeps unknown-type blocks instead of dropping them. Relocated the Phase 1 proto test to `web/test/` (was being deleted by buf `clean:true`). Verified end-to-end: known layout renders identically, unknown block shows the placeholder. `make test-web` + `go test ./...` + web build all green.

Step 7 (Phase 6 complete): Block-aware rasterization + per-segment heat. New `internal/app/rasterize.go` implements a region-aware rasterizer (Atkinson error-diffusion dithering confined per band + gamma tone curve + threshold), driven by per-block `render` overrides mapped onto per-block bounding boxes. Added `data-block-id`/`data-block-type` to block wrappers + `collectBlockMetricsJS`; `blockRasterRegions`/`blockHeatRegions` build raster + heat regions; `pngToBitmapSupersampledRegions` applies them. `printer.go` `densityBands`+`sendBitmapWithHeat` print a page in density bands (text hot 38 / photo cool 20). Verified: a gradient photo dithers to a clean Atkinson halftone while text stays crisp (visual zoom + 108 transitions/row); a mixed page printed with per-segment heat (7 segments). rasterize/heat unit tests added; go+web+lint green.

Step 6 (Phase 5 complete): Typed RenderOptions. New `internal/app/renderopts.go` parses the layout `render:` block (and per-block `render:`) into the typed `layoutv1.RenderOptions` via protojson with validation, replacing intFromRenderOptions/stringFromRenderOptions (removed). `applyRenderOptions` overlays only set fields onto the internal struct; added RasterMode/Gamma/PrinterDensity/PrinterSpeed to it. `perBlockRenderOptions` extracts per-block overrides (for Phase 6). Fixed `layoutJSONFromObjectOrDefault` to extract flat top-level `render:` (previously only the wrapped form). Printer density applied at print time via new `setPrinterDensity`. Also (user requests this turn): printed two examples on the thermal printer (crisp + inline-theme, density 38); added layout-level `margin` control (commit c46d921). Verified: `render.threshold:90` applies, `:300` errors; go+web tests green.

Step 5 (Phase 4 complete): Data-driven themes + hinted fonts. Embedded DejaVu Serif (4 faces) + DejaVu Sans (2 faces) as subset woff into `web/src/fonts-embedded.css` (fonttools; woff since brotli/woff2 unavailable). Added built-in `crisp`/`crispsans` DejaVu themes. `resolveThemeSpec` lets a layout's `theme` be a built-in name OR an inline object (base + colors + fontPalette/fontDisplay + presetOverrides) patched over the base with no code change; wired `inlineTheme`/`themePresets` state + `mergePresetMaps` so theme preset overrides layer under layout typography (default<-theme<-layout<-block). Verified on paper: `crisp` renders crisp DejaVu Serif; an inline DejaVu-Sans theme with bold body/caption overrides prints legibly. Tests green.

Step 4 (Phase 3 complete): Typography presets. Added `web/src/typography/presets.js` — DEFAULT_PRESETS (title/word/body/emphasis/caption/small/overline/meta/...) with the ALMANACH-PIXELFONT recipe baked in (bigger sizes, minSize floor, bold body/small, bold-italic quotes), `resolveStyle` (merge default<-layout preset<-block style, bodyScale, minSize, case/italic->CSS), `makePresetResolver` + node test. Wired `theme.preset(name, ...overrides)` into the studio; migrated all block components off inline `theme.fs(n)`/font onto presets (glyphs/icons keep fs). Added layout-level `typography.presets` + per-block `style` plumbing (parse, state, headless load, file import, buildLayoutJson round-trip; adapters pass block style). Verified on paper: knowledge-strip is markedly more legible (heavier body, bold-italic quotes); an override layout confirms all three resolution layers (layout body override bolds/enlarges, per-block style flips to italic/lighter). `make test-web` + `go test ./...` + web build green.
